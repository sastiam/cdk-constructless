# AlertsTopic

## Purpose

Cost alerts are only useful if a person receives them. AWS Budgets and Cost Anomaly Detection publish to an SNS topic, and that topic's policy must allow the service to publish; `SnsAction` does not add that statement, so a hand-written topic is easy to leave unable to receive Budgets alerts. This construct creates a topic for human notifications only. It adds the Budgets publish statement (on by default), an optional Cost Anomaly Detection statement, e-mail subscriptions and TLS-only access. The topic is not a trigger for automation: do not subscribe Lambda functions, SSM or any other automation to it, because a first-cent alert on a topic that also stops instances would stop every instance. To act on spend, use a Budget Action instead.

## Resources created

| CloudFormation type | Count | Notes |
| --- | --- | --- |
| `AWS::SNS::Topic` | 1 | Always created, with `enforceSSL` set to `true`. The name is `topicName` when given, otherwise generated by CDK. Encrypted with the key in `masterKey` when that prop is given. |
| `AWS::SNS::TopicPolicy` | 1 | Always created. It holds the TLS deny statement, the `AWSBudgetsSNSPublishingPermissions` statement when `allowBudgets` is `true` (the default), and the `AWSAnomalyDetectionSNSPublishingPermissions` statement when `allowCostAnomalyDetection` is `true`. |
| `AWS::SNS::Subscription` | 1 per address | Created only when `emails` has items. Each one has protocol `email`. |

## Props and defaults

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `topicName` | `string` | a name generated by CDK | The physical name of the SNS topic. Leave it unset to let CDK generate a unique name. |
| `emails` | `string[]` | `[]` (no e-mail subscribers) | The e-mail addresses that subscribe to the topic. Between 0 and 10 items; each must be a valid e-mail address. Each address must confirm its subscription before it receives notifications. |
| `allowBudgets` | `boolean` | `true` | Whether AWS Budgets may publish to the topic. Adds the `AWSBudgetsSNSPublishingPermissions` statement, which is restricted to budgets in this account. |
| `allowCostAnomalyDetection` | `boolean` | `false` | Whether Cost Anomaly Detection may publish to the topic. Adds the `AWSAnomalyDetectionSNSPublishingPermissions` statement. |
| `masterKey` | `kms.IKey` | none (the topic is not encrypted with a customer managed key) | The customer managed KMS key that encrypts the topic. When given, Budgets (and Cost Anomaly Detection when allowed) are granted `kms:GenerateDataKey*` and `kms:Decrypt` on the key. The key is not created by this construct. |

The wrapped topic is exposed as the `topic` property (`sns.Topic`). Pass it to a `CostBudget` with its `topic` prop.

## Cost impact

**None** from the construct's own resources: it creates one `AWS::SNS::Topic`, one `AWS::SNS::TopicPolicy` and no fixed-cost resource. The SNS price is not recorded in [`../aws-facts.md`](../aws-facts.md) yet, so this page gives no SNS USD figure.

A `masterKey` is not created by this construct. If you pass one, that customer managed key is a **fixed** charge of 1 USD per month that you pay for. See [`../aws-facts.md`](../aws-facts.md).

## Verified AWS facts

- The Budgets topic policy allows `budgets.amazonaws.com` to publish with `aws:SourceAccount` and `aws:SourceArn` `arn:aws:budgets::<account>:*`, and the topic must be in the same account. See [`../aws-facts.md`](../aws-facts.md).
- Cost Anomaly Detection publishes to SNS as `costalerts.amazonaws.com`. See [`../aws-facts.md`](../aws-facts.md).
- A KMS customer managed key costs 1 USD per month. See [`../aws-facts.md`](../aws-facts.md).

## Limits and risks

- **Notification-only.** The props accept only e-mail subscriptions and no automation target. The wrapped `topic` is public, though, so other code can still subscribe to it. Do not subscribe Lambda functions, SSM or any other automation to this topic; use a Budget Action to act on spend.
- **Same account.** The Budgets statement is restricted with `aws:SourceAccount` set to the stack account and `aws:SourceArn` set to `arn:<partition>:budgets::<account>:*`. A budget in another account cannot publish to this topic, so create the topic in the same account as the budget that uses it.
- **Wildcard budget scope.** The `aws:SourceArn` condition matches every budget in the account, not one named budget.
- **Cost Anomaly Detection has no source condition.** When `allowCostAnomalyDetection` is `true`, its statement allows `costalerts.amazonaws.com` to publish to the topic without an `aws:SourceAccount` or `aws:SourceArn` condition. It is off by default; enable it only when you accept that.
- **At most 10 e-mail addresses.** `emails` must contain between 0 and 10 items, otherwise construction fails with `emails must contain between 0 and 10 items, got <n>`. This cap is a library choice, not an AWS limit.
- **Invalid e-mail.** Each entry must match the syntax check `/^[^\s@]+@[^\s@]+\.[^\s@]+$/`, otherwise construction fails with `emails contains an invalid email "<value>"`. The check is syntactic only: it does not prove that the address exists.
- **Subscription confirmation.** Each e-mail address receives a subscription confirmation message and must confirm it before it receives notifications. Until it is confirmed, the subscription stays pending and no alert is delivered to that address.
- **Customer managed key.** Without `masterKey`, the topic uses the AWS managed key. With `masterKey`, the key costs a fixed 1 USD per month. The construct grants `kms:GenerateDataKey*` and `kms:Decrypt` on that key to each enabled service, and it does not create the key.
- **cdk-nag.** Without `masterKey`, the construct suppresses finding `AwsSolutions-SNS2` on the topic with the reason `A KMS key costs 1 USD per month; this topic carries no sensitive data; pass masterKey to encrypt`. With `masterKey`, no suppression is added.

## Example

```typescript
import { App, Stack } from 'aws-cdk-lib';
import { AlertsTopic, CostBudget } from 'cdk-constructless';

const app = new App();
const stack = new Stack(app, 'Example', {
  env: { account: '123456789012', region: 'eu-west-1' },
});

// Notification-only topic that e-mails alerts to one address.
const alerts = new AlertsTopic(stack, 'Alerts', {
  emails: ['alerts@example.com'],
});

// The budget publishes its threshold notifications to the topic.
new CostBudget(stack, 'MonthlyBudget', {
  limitUsd: 5,
  topic: alerts.topic,
});
```
