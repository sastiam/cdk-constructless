# BillingAlarm

## Purpose

AWS Budgets is the primary guard against unexpected spend, but a budget is only one control. This construct adds a CloudWatch alarm on the `AWS/Billing` `EstimatedCharges` metric that notifies an SNS topic when the estimated charges in USD exceed a threshold. It is a **backup to Budgets, not a replacement**: it reacts to current estimated charges, it only notifies, and it does not stop any resource. The billing metric only exists in `us-east-1`, so the construct refuses to synthesize in any other region, because an alarm created there would never fire. Billing alerts must be enabled in the account's Billing preferences first (see the limits below).

## Resources created

| CloudFormation type | Count | Notes |
| --- | --- | --- |
| `AWS::CloudWatch::Alarm` | 1 | Always created, in the stack's region (`us-east-1`). The name is `alarmName` when given, otherwise generated by CDK. The SNS action adds no resource: the alarm only references the topic in `AlarmActions`. The construct creates no log group, no topic and no key. |

## Props and defaults

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `thresholdUsd` | `number` | none (required) | The estimated charges in USD above which the alarm enters the ALARM state. Must be greater than 0. |
| `topic` | `sns.ITopic` | none (required) | The SNS topic notified when the alarm enters the ALARM state. The topic policy must allow the alarm to publish. |
| `alarmName` | `string` | a name generated by CDK | The physical name of the alarm. Leave it unset to let CDK generate a unique name. |
| `linkedAccountId` | `string` | none (the alarm watches the total estimated charges of the payer account) | The 12-digit account ID whose estimated charges the alarm watches. Adds the `LinkedAccount` dimension. Use it only when the payer account publishes per-account billing metrics. |

The wrapped alarm is exposed as the `alarm` property (`cloudwatch.Alarm`).

## Cost impact

**None** from the construct's own resources: it creates one `AWS::CloudWatch::Alarm` and no fixed-cost resource. The free tier includes 10 standard-resolution alarm metrics per month (see [`../aws-facts.md`](../aws-facts.md)). Alarms beyond the free tier are charged, but that price is not recorded in `../aws-facts.md` yet, so this page gives no USD figure for it.

## Verified AWS facts

- Billing metric data is stored in `us-east-1`, represents worldwide charges and is USD only; the recommended statistic is `Maximum` with a 6-hour period. See [`../aws-facts.md`](../aws-facts.md).
- CloudWatch free tier includes 10 standard-resolution alarm metrics per month. See [`../aws-facts.md`](../aws-facts.md).

## Limits and risks

- **Billing alerts must be enabled first.** Enable billing alerts in the Billing preferences of the payer account before you deploy. This setting cannot be disabled. Data takes about 15 minutes to appear after it is enabled. Until data exists, the alarm has nothing to evaluate.
- **Missing data is not breaching.** `treatMissingData` is `notBreaching`. When no data arrives (for example, because billing alerts are not enabled), the alarm stays in OK and never fires. The alarm does not warn you about missing data.
- **us-east-1 only.** When the stack region is resolved and is not `us-east-1`, synthesis fails with `BillingAlarm requires region us-east-1, got <region>`. When the stack is environment-agnostic, the alarm is created and the warning `cdk-constructless:unresolved-region` is emitted. Deploy the stack to `us-east-1` or the alarm never fires.
- **Backup to Budgets.** The alarm reacts to current estimated charges only and notifies only. Keep a `CostBudget` for the monthly limit, and use a Budget Action when spend must stop resources.
- **Detection latency.** The metric period is 6 hours with one evaluation period. A charge above the threshold can take up to one 6-hour period, plus the data delay, to reach the ALARM state.
- **USD only.** `thresholdUsd` is compared with USD estimated charges. The construct does not support other currencies.
- **Topic policy.** The construct does not add a topic policy statement for CloudWatch, and `AlertsTopic` has none: its policy holds only the Budgets, Cost Anomaly Detection and TLS statements. An alarm wired to an `AlertsTopic` may therefore not deliver notifications. Before you rely on it, force the alarm into ALARM with `aws cloudwatch set-alarm-state --alarm-name <name> --state-value ALARM --state-reason test --region us-east-1` and check that the notification arrives.
- **Linked account.** The `LinkedAccount` dimension exists only when the payer account publishes per-account billing metrics. Check it with `aws cloudwatch list-metrics --namespace AWS/Billing --region us-east-1` before you set `linkedAccountId`. If the dimension does not exist, the alarm has no data and stays in OK.
- **cdk-nag.** The construct adds no `suppressNag` entry, so it suppresses no finding.

## Example

```typescript
import { App, Stack } from 'aws-cdk-lib';
import { AlertsTopic, BillingAlarm } from 'cdk-constructless';

const app = new App();
const stack = new Stack(app, 'Example', {
  env: { account: '123456789012', region: 'us-east-1' },
});

// Notification topic that e-mails alerts to one address.
const alerts = new AlertsTopic(stack, 'Alerts', {
  emails: ['alerts@example.com'],
});

// Alarm when the estimated charges exceed 5 USD. Must be deployed in us-east-1.
new BillingAlarm(stack, 'EstimatedChargesAlarm', {
  thresholdUsd: 5,
  topic: alerts.topic,
});
```
