# BudgetActionExecutionRole

## Purpose

A Budget Action runs with an IAM role that AWS Budgets assumes when a budget threshold is crossed. A hand-written role is easy to get wrong: it can miss the confused-deputy conditions, so another account's budget could assume it, or it can grant more than the action needs. This construct creates that role with the trust conditions that AWS documents, and it grants only the permissions needed to stop one instance type through SSM automation, to attach and detach one IAM deny policy, or to attach, detach and describe service control policies (SCPs). The role does not start anything and does not create the Budget Action itself.

## Resources created

| CloudFormation type | Count | Notes |
| --- | --- | --- |
| `AWS::IAM::Role` | 1 | Always created. Its trust policy allows `sts:AssumeRole` to `budgets.amazonaws.com` only when `aws:SourceAccount` is the stack account and `aws:SourceArn` matches `arn:<partition>:budgets::<account>:budget/*`. The role has no managed policies attached. |
| `AWS::IAM::Policy` | 1 | The inline `DefaultPolicy` that holds the stop, attach and SCP statements. CDK creates it on the first `allowStopInstances`, `allowApplyIamPolicy` or `allowApplyScpPolicy` call, so it is absent when none is called. Each target, each policy and the SCP statement add their statements once. |

## Props and defaults

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `roleName` | `string` | a name generated by CDK | The physical name of the IAM role. Leave it unset to let CDK generate a unique name. |

The construct has three methods, `allowStopInstances(target: StopInstancesTarget): void`, `allowApplyIamPolicy(policy: IManagedPolicy): void` (`IManagedPolicy` from `aws-cdk-lib/aws-iam`) and `allowApplyScpPolicy(): void`. They are not props. `allowStopInstances` grants the permissions in the first table below for one target. `allowApplyIamPolicy` grants the permissions in the second table for one policy ARN. `allowApplyScpPolicy` grants the permissions in the third table once for the whole role. Calling any method again for the same target, policy or SCP grant adds nothing.

`StopInstancesTarget` has two members: `EC2` (value `'EC2'`) and `RDS` (value `'RDS'`).

### Permissions per `StopInstancesTarget`

| Target | SSM document | Statement | Actions | Resources | Condition |
| --- | --- | --- | --- | --- | --- |
| `EC2` | `AWS-StopEC2Instance` | Stop | `ec2:DescribeInstanceStatus`, `ec2:StopInstances` | `*` | `ForAnyValue:StringEquals` `aws:CalledVia` `ssm.amazonaws.com` |
| `EC2` | `AWS-StopEC2Instance` | Run automation | `ssm:StartAutomationExecution` | `document/AWS-StopEC2Instance`, `automation-execution/*`, `automation-definition/AWS-StopEC2Instance:*` | none |
| `RDS` | `AWS-StopRdsInstance` | Stop | `rds:DescribeDBInstances`, `rds:StopDBInstance` | `*` | `ForAnyValue:StringEquals` `aws:CalledVia` `ssm.amazonaws.com` |
| `RDS` | `AWS-StopRdsInstance` | Run automation | `ssm:StartAutomationExecution` | `document/AWS-StopRdsInstance`, `automation-execution/*`, `automation-definition/AWS-StopRdsInstance:*` | none |

The SSM resources are ARNs of the form `arn:<partition>:ssm:*:*:<resource>`, where `<partition>` is the stack's partition. The `ec2:` and `rds:` stop actions are granted only when the call comes through SSM. No `ec2:StartInstances` or `rds:StartDBInstance` action is ever granted.

### Permissions for `allowApplyIamPolicy`

| Statement | Actions | Resources | Condition |
| --- | --- | --- | --- |
| Attach and detach | `iam:AttachRolePolicy`, `iam:DetachRolePolicy`, `iam:AttachUserPolicy`, `iam:DetachUserPolicy`, `iam:AttachGroupPolicy`, `iam:DetachGroupPolicy` | `*` | `ArnEquals` `iam:PolicyARN` equal to the ARN of the policy passed to the method |

The statement lets the role attach and detach only that one policy, such as the deny policy of [BudgetDenyAction](BudgetDenyAction.md), to roles, users and groups. No other IAM action is granted.

### Permissions for `allowApplyScpPolicy`

| Statement | Actions | Resources | Condition |
| --- | --- | --- | --- |
| Attach, detach and describe SCPs | `organizations:AttachPolicy`, `organizations:DetachPolicy`, `organizations:DescribePolicy` | `*` | none |

The statement lets the role attach, detach and describe service control policies for any target. The targets are known only when the Budget Action runs, so the grant cannot name them in advance. It is used by [BudgetScpAction](BudgetScpAction.md). Only a management account can apply SCPs through Budget Actions, so the grant is useful only in the management account.

## Cost impact

**None** from the construct's own resources: it creates one `AWS::IAM::Role` and one `AWS::IAM::Policy`, and no fixed-cost resource. The IAM price is not recorded in [`../aws-facts.md`](../aws-facts.md) yet, so this page gives no USD figure.

## Verified AWS facts

- The trust policy uses `budgets.amazonaws.com` with `aws:SourceAccount` and `aws:SourceArn` as in the AWS example policies. See [`../aws-facts.md`](../aws-facts.md).
- The AWS managed policy `AWSBudgetsActions_RolePolicyForResourceAdministrationWithSSM` grants EC2 and RDS stop through `ssm.amazonaws.com` and `ssm:StartAutomationExecution` on the `AWS-Stop*` documents (updated 2026-04-07). This construct grants the stop part of that policy only. See [`../aws-facts.md`](../aws-facts.md).
- Only a management account can apply SCPs through Budget Actions, so `allowApplyScpPolicy` is useful only in the management account. See [`../aws-facts.md`](../aws-facts.md).

## Limits and risks

- **Stop and attach only.** The AWS managed policy also grants Start actions. This construct deliberately does not grant them, so a Budget Action that uses this role can stop instances and RDS databases, and attach or detach the policies you allow, but cannot start instances or databases again. Restarting needs permissions that this role does not hold.
- **Permissions only for what you allow.** The role receives no stop permission until `allowStopInstances` is called, and no attach permission until `allowApplyIamPolicy` is called. Allow only the targets and policies your Budget Actions need.
- **Trust scope.** `aws:SourceArn` matches every budget in the account (`budget/*`), not one named budget. Any budget in the stack's account can be configured to run its Budget Action with this role.
- **SCP permissions reach every policy.** `allowApplyScpPolicy` grants `organizations:AttachPolicy`, `organizations:DetachPolicy` and `organizations:DescribePolicy` on `*`. A Budget Action that uses this role can attach and detach any SCP in the organization to any target, not only the SCP of one [BudgetScpAction](BudgetScpAction.md). The construct cannot narrow the grant, because the targets are known only at action time. Grant it only in the management account, where Budget Actions can apply SCPs.
- **cdk-nag suppressions.** The stop statements use wildcard resources, so `AwsSolutions-IAM5` reports one finding per wildcard resource on the role's default policy. Each target's `allowStopInstances` call acknowledges its findings with `suppressNag` and the reason `Budget Actions stop instances through SSM automation documents; AWS documents these wildcard resources`. The finding ids are:
  - `AwsSolutions-IAM5[Resource::*]` (both targets; the attach statement of `allowApplyIamPolicy` also reports this id, which that method acknowledges with the reason `IAM attach actions are scoped by iam:PolicyARN`; the SCP statement of `allowApplyScpPolicy` reports this id too, which that method acknowledges with the reason `SCP attach targets are only known at action time`)
  - `AwsSolutions-IAM5[Resource::arn:<AWS::Partition>:ssm:*:*:document/AWS-StopEC2Instance]` (`EC2`)
  - `AwsSolutions-IAM5[Resource::arn:<AWS::Partition>:ssm:*:*:automation-execution/*]` (both targets)
  - `AwsSolutions-IAM5[Resource::arn:<AWS::Partition>:ssm:*:*:automation-definition/AWS-StopEC2Instance:*]` (`EC2`)
  - `AwsSolutions-IAM5[Resource::arn:<AWS::Partition>:ssm:*:*:document/AWS-StopRdsInstance]` (`RDS`)
  - `AwsSolutions-IAM5[Resource::arn:<AWS::Partition>:ssm:*:*:automation-definition/AWS-StopRdsInstance:*]` (`RDS`)

  The stop actions cannot be scoped to instance ARNs through SSM automation without per-instance policies, which this construct does not create.

## Example

```typescript
import { App, Stack } from 'aws-cdk-lib';
import { BudgetActionExecutionRole, StopInstancesTarget } from 'cdk-constructless';

const app = new App();
const stack = new Stack(app, 'Example', {
  env: { account: '123456789012', region: 'eu-west-1' },
});

// Role that AWS Budgets assumes to stop EC2 and RDS instances through SSM.
const executionRole = new BudgetActionExecutionRole(stack, 'BudgetActionExecutionRole');
executionRole.allowStopInstances(StopInstancesTarget.EC2);
executionRole.allowStopInstances(StopInstancesTarget.RDS);
```
