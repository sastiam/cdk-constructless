# CostAnomalyGuard

## Purpose

A fixed USD threshold misses unusual spend. A service can suddenly cost ten times more than usual while the total stays under the monthly budget, so a `CostBudget` never reports it. Cost Anomaly Detection watches each service's spend against its expected pattern and reports the anomalies. This construct creates the anomaly monitor and the subscription that sends the alert, and it sets the alert threshold as an absolute USD impact through `ThresholdExpression`. It notifies only: it does not stop any resource. Use a Budget Action when spend must stop resources.

## Resources created

| CloudFormation type | Count | Notes |
| --- | --- | --- |
| `AWS::CE::AnomalyMonitor` | 1 when `monitor` is `services` (the default) or `linkedAccounts`; 0 when `monitor.kind` is `existing` | The monitor is `DIMENSIONAL` on the `SERVICE` dimension for `services`, and `CUSTOM` on the `LINKED_ACCOUNT` dimension for `linkedAccounts`. The name is `monitorName` when given, otherwise generated by CDK. Not created when `monitor.kind` is `existing`. |
| `AWS::CE::AnomalySubscription` | 1 | Always created. The name is `subscriptionName` when given, otherwise generated by CDK. It holds one subscriber per entry of `emails`, or one `SNS` subscriber for `topic`. |

The construct creates no IAM role, no log group, no topic and no key.

## Props and defaults

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `monitor` | `AnomalyMonitorSource` | `{ kind: 'services' }` | The monitor that Cost Anomaly Detection watches. `linkedAccounts` takes between 1 and 10 account IDs, each a 12-digit account ID. `existing` takes the ARN of a monitor that already exists, for example one that AWS created on its own. |
| `monitorName` | `string` | a name generated by CDK (Names.uniqueResourceName, at most 100 characters) | The physical name of the anomaly monitor. Leave it unset to let CDK generate a unique name (at most 100 characters). Ignored when `monitor.kind` is `existing`. |
| `subscriptionName` | `string` | a name generated by CDK (Names.uniqueResourceName, at most 100 characters) | The physical name of the anomaly subscription. Leave it unset to let CDK generate a unique name (at most 100 characters). |
| `emails` | `string[]` | none (provide emails or topic) | The e-mail addresses that receive the anomaly notifications. Between 1 and 10 items; each must be a valid e-mail address. Give either `emails` (non-empty) or `topic`, never both. E-mail subscribers require `DAILY` or `WEEKLY` frequency. |
| `topic` | `sns.ITopic` | none (provide emails or topic) | The SNS topic that receives the anomaly notifications. Give either `emails` (non-empty) or `topic`, never both. SNS subscribers require `IMMEDIATE` frequency. The topic policy must allow `costalerts.amazonaws.com` to publish: create it with `AlertsTopic` and `allowCostAnomalyDetection: true`. |
| `frequency` | `AnomalyFrequency` | `DAILY` for e-mail, `IMMEDIATE` for a topic | How often the subscription sends notifications. `DAILY` and `WEEKLY` are valid for `emails`; `IMMEDIATE` is valid for `topic`. |
| `thresholdUsd` | `number` | `1` | The absolute total impact in USD at or above which an anomaly is reported. Must be greater than 0. |

The wrapped resources are exposed as the `monitorArn` property (`string`, the ARN of the created or existing monitor), the `monitor` property (`ce.CfnAnomalyMonitor`, `undefined` when `monitor.kind` is `existing`) and the `subscription` property (`ce.CfnAnomalySubscription`).

## Cost impact

**None** from the construct's own resources: it creates one `AWS::CE::AnomalyMonitor` and one `AWS::CE::AnomalySubscription` and no fixed-cost resource. The price of Cost Anomaly Detection is **unverified**: the product and FAQ pages state no price beyond the default configuration having no cost, and no USD figure is recorded for it, so this page gives no USD figure. See [`../aws-facts.md`](../aws-facts.md).

## Verified AWS facts

- Anomaly subscriptions notify by e-mail for `DAILY` and `WEEKLY` and by SNS for `IMMEDIATE`. `Threshold` is deprecated in favour of `ThresholdExpression`, and both cannot be set; the construct writes only `ThresholdExpression`. See [`../aws-facts.md`](../aws-facts.md).
- An anomaly subscription takes up to 10 e-mail recipients or 1 SNS topic, and a customer managed monitor takes up to 10 values (linked accounts or tags). See [`../aws-facts.md`](../aws-facts.md).
- Cost Anomaly Detection publishes to SNS as `costalerts.amazonaws.com`, so the topic policy must allow that principal. See [`../aws-facts.md`](../aws-facts.md).
- Unverified: the price of Cost Anomaly Detection beyond the default configuration having no cost. See [`../aws-facts.md`](../aws-facts.md).

## Limits and risks

- **Subscriber count.** `emails` takes 1 to 10 addresses, and `monitor.accountIds` takes 1 to 10 account IDs. The construct checks both counts and throws `emails must contain between 1 and 10 items, got <n>` or `monitor.accountIds must contain between 1 and 10 items, got <n>` when a count is outside the range.
- **One destination per subscription.** A subscription takes either e-mail addresses or one SNS topic, never both. Giving both `emails` and `topic`, or neither, throws `provide emails or a topic, not both`.
- **Frequency must match the destination.** `IMMEDIATE` with `emails` throws `email subscribers require DAILY or WEEKLY frequency`. Any frequency other than `IMMEDIATE` with `topic` throws `SNS subscribers require IMMEDIATE frequency`.
- **Threshold.** `thresholdUsd` must be greater than 0; 0 throws `thresholdUsd must be greater than 0, got 0`. The threshold is an absolute USD impact, not a percentage. The construct never writes the deprecated `Threshold`.
- **Topic policy.** The SNS topic must allow `costalerts.amazonaws.com` to publish. A hand-written topic that lacks this statement receives no anomaly notifications. Create the topic with `AlertsTopic` and `allowCostAnomalyDetection: true`.
- **Duplicate monitor.** AWS may already have created a services monitor in the account. A second monitor duplicates the anomaly stream, so reuse the existing monitor with `monitor: { kind: 'existing', monitorArn }` when it is present. The construct does not look the monitor up.
- **Account IDs.** Each `monitor.accountIds` entry must be a 12-digit account ID; any other value throws `monitor.accountIds must be 12-digit account IDs, got "<id>"`. Unresolved tokens are not checked until deploy time.
- **Names.** `monitorName` and `subscriptionName` are physical names; leave them unset unless a fixed name is needed. `monitorName` is ignored for `existing`.
- **Notify only.** The construct does not stop or change any resource. Keep a `CostBudget` for the monthly limit, and use a Budget Action when spend must stop resources.
- **cdk-nag.** The construct creates no IAM role and no fixed-cost resource, so it adds no finding and has no `suppressNag` entry.

## Example

```typescript
import { App, Stack } from 'aws-cdk-lib';
import { CostAnomalyGuard } from 'cdk-constructless';

const app = new App();
const stack = new Stack(app, 'Example', {
  env: { account: '123456789012', region: 'eu-west-1' },
});

// Daily e-mail for any service whose anomaly impact is at least 10 USD.
new CostAnomalyGuard(stack, 'CostAnomalyGuard', {
  emails: ['alerts@example.com'],
  thresholdUsd: 10,
});
```
