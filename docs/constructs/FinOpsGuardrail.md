# FinOpsGuardrail

## Purpose

A lab account can run up a bill while nobody is watching, and a single alert does not stop the spend. `FinOpsGuardrail` puts the recommended setup behind one props object: a monthly USD budget that notifies a notification-only SNS topic, an optional billing alarm as a backup to the budget, and optional Budget Actions that stop listed instances or deny compute when a threshold is crossed. The alerts topic is for people only. The Budget Actions notify their own e-mail subscribers, so a first-cent alert never triggers automation. Budgets data refreshes only up to three times a day, so this is a guardrail, not a hard cap.

## Resources created

| CloudFormation type | Count | Notes |
| --- | --- | --- |
| `AWS::SNS::Topic` | 1 | The alerts topic (`alerts.topic`), created as an `AlertsTopic` with TLS enforced. The guardrail never passes a KMS key, so no KMS key is created. |
| `AWS::SNS::TopicPolicy` | 1 | The `AWSBudgetsSNSPublishingPermissions` statement, restricted to budgets in this account. |
| `AWS::SNS::Subscription` | One per `emails` entry (0 to 10) | E-mail subscriptions to the alerts topic. Each address must confirm its subscription. |
| `AWS::Budgets::Budget` | 1 | The `CostBudget`, which notifies the alerts topic at every threshold. |
| `AWS::CloudWatch::Alarm` | 0 or 1 | Created only when `billingAlarmThresholdUsd` is set, as the `BillingAlarm`. It is in `us-east-1` and notifies the alerts topic. |
| `AWS::IAM::ManagedPolicy` | 0 or 1 | Created only when `denyCompute` is set, as the `DenyPolicy` of the `BudgetDenyAction`. |
| `AWS::Budgets::BudgetsAction` | 0, 1 or 2 | One for `stopInstances` (`StopInstances`) and one for `denyCompute` (`DenyCompute`). Each one notifies the `emails` subscribers only. |
| `AWS::IAM::Role` | 0 or 1 | Created when `stopInstances` or `denyCompute` is set. When both are set, one shared `ActionsRole` is created. When only one is set, that action creates its own execution role. |
| `AWS::IAM::Policy` | 0 or 1 | The default policy of the execution role, created when any Budget Action is set. |

## Props and defaults

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `limitUsd` | `number` | none (required) | The monthly budget limit in USD. Must be greater than 0. |
| `emails` | `string[]` | none (required) | The e-mail addresses that receive the alerts topic notifications and the Budget Action notifications. Between 0 and 10 items; each must be a valid e-mail address and must confirm its subscription before it receives notifications. A Budget Action needs between 1 and 11 subscribers, so set at least one address when `stopInstances` or `denyCompute` is given. |
| `thresholds` | `BudgetThreshold[]` | `ACTUAL 60`, `ACTUAL 80`, `ACTUAL 100` and `FORECASTED 100` percent | The thresholds at which the budget notifies the alerts topic. Between 1 and 5 items. |
| `budgetName` | `string` | a name generated by CDK | The physical name of the budget. Leave it unset to let CDK generate a unique name. |
| `billingAlarmThresholdUsd` | `number` | none (no billing alarm is created) | The estimated charges in USD above which the billing alarm enters the ALARM state. Creates a `BillingAlarm` in `us-east-1` that notifies the alerts topic. Must be greater than 0 when set. |
| `stopInstances` | object | none (no stop action is created) | When set, creates a `BudgetStopInstancesAction` that stops the listed instances when the threshold is crossed. It notifies the `emails` subscribers, never the alerts topic. |
| `stopInstances.target` | `StopInstancesTarget` | none (required) | The instance type that the action stops: `StopInstancesTarget.EC2` or `StopInstancesTarget.RDS`. |
| `stopInstances.instanceIds` | `string[]` | none (required) | The instance IDs to stop. Between 1 and 100 items. |
| `stopInstances.threshold` | `number` | none (required) | The percentage of `limitUsd` that runs the action, from 0.01 to 1000. |
| `denyCompute` | object | none (no deny action is created) | When set, creates a `BudgetDenyAction` that attaches a deny policy to the given principals when the threshold is crossed. It notifies the `emails` subscribers, never the alerts topic. |
| `denyCompute.roles` | `iam.IRole[]` | `[]` (no roles) | The roles that the deny policy is attached to. |
| `denyCompute.users` | `iam.IUser[]` | `[]` (no users) | The users that the deny policy is attached to. |
| `denyCompute.groups` | `iam.IGroup[]` | `[]` (no groups) | The groups that the deny policy is attached to. At least one role, user or group is required. |
| `denyCompute.threshold` | `number` | none (required) | The percentage of `limitUsd` that runs the action, from 0.01 to 1000. |
| `denyCompute.deniedActions` | `string[]` | `DEFAULT_DENIED_COMPUTE_ACTIONS`: `ec2:RunInstances`, `ec2:StartInstances`, `lambda:CreateFunction`, `ecs:CreateService`, `ecs:RunTask`, `rds:CreateDBInstance`, `rds:StartDBInstance` | The IAM actions that the deny policy denies. Each entry must look like `service:Action`. |

## Cost impact

**None** for the default guardrail: the budget, the alerts topic and the e-mail subscriptions create no fixed-cost resource, and the guardrail creates no KMS key. The optional parts are not all free. The billing alarm costs nothing while the account stays inside the CloudWatch free tier. The Budget Actions are **variable**: the first two action-enabled budgets per account are free each month, and each additional one costs 0.10 USD per day.

| Part | Charge | USD figure | Fact in [`../aws-facts.md`](../aws-facts.md) |
| --- | --- | --- | --- |
| `AlertsTopic` | A KMS customer managed key. Not created: the guardrail never passes `masterKey`. | 0 USD from this construct. A customer managed key costs 1 USD per month if you add one yourself. | A KMS customer managed key costs 1 USD per month |
| `BillingAlarm` | One CloudWatch alarm on `EstimatedCharges` | 0 USD inside the free tier of 10 standard-resolution alarm metrics per month. No price above the free tier is recorded. | CloudWatch free tier includes 10 standard-resolution alarm metrics per month |
| `StopInstances`, `DenyCompute` | Budget Actions on the budget | 0 USD while the account has at most two action-enabled budgets. Each additional one costs 0.10 USD per day. | The first two action-enabled budgets per account are free each month; each additional one costs 0.10 USD per day |
| `CostBudget`, `AlertsTopic` (SNS) | The budget and the SNS topic | No USD figure is recorded in aws-facts.md, so this page gives none. | none recorded |

The example below puts both Budget Actions on one budget, which counts as one action-enabled budget. It therefore costs 0 USD per month while the account has no more than two action-enabled budgets in total.

## Verified AWS facts

- Budgets data refreshes up to three times a day, 8 to 12 hours apart, so the budget notifications and the Budget Actions can run long after the spend occurred. See [`../aws-facts.md`](../aws-facts.md).
- Assumption, to verify before 1.0: a budget supports at most 5 notifications and 10 e-mail subscribers per notification. The default thresholds produce 4 notifications, and `thresholds` and `emails` are checked against 5 and 10. See [`../aws-facts.md`](../aws-facts.md).
- The Budget Actions execution role trust policy allows only `budgets.amazonaws.com`, with `aws:SourceAccount` and `aws:SourceArn` set to this account's budgets. See [`../aws-facts.md`](../aws-facts.md).
- The `AWSBudgetsActions_RolePolicyForResourceAdministrationWithSSM` managed policy grants EC2 and RDS stop through `ssm.amazonaws.com` on `AWS-Stop*` documents. See [`../aws-facts.md`](../aws-facts.md).
- `AWS::Budgets::BudgetsAction` requires `ActionThreshold`, `ActionType`, `BudgetName`, `Definition`, `ExecutionRoleArn`, `NotificationType` and `Subscribers`, and an SSM definition takes 1 to 100 instance IDs. See [`../aws-facts.md`](../aws-facts.md).
- A reverted Budget Action is not evaluated again in the same period unless it is reset. See [`../aws-facts.md`](../aws-facts.md).
- Unconfirmed: whether Budget Actions are available on the AWS Free Plan. See [`../aws-facts.md`](../aws-facts.md).
- The Budgets statement of the SNS topic policy allows `budgets.amazonaws.com` to publish with `aws:SourceAccount` and `aws:SourceArn`, and the topic must be in the same account as the budget. See [`../aws-facts.md`](../aws-facts.md).
- The billing metric is in `us-east-1`, is USD only and represents worldwide charges. The recommended statistic is `Maximum` with a 6-hour period, which the alarm uses. See [`../aws-facts.md`](../aws-facts.md).
- The CloudWatch free tier includes 10 standard-resolution alarm metrics per month. See [`../aws-facts.md`](../aws-facts.md).
- The first two action-enabled budgets per account are free each month, and each additional one costs 0.10 USD per day. See [`../aws-facts.md`](../aws-facts.md).

## Limits and risks

- **Not a hard cap.** Budgets data refreshes up to three times a day, so spend can pass `limitUsd` before a notification is sent. The actions stop the listed instances or deny compute only after the threshold is seen in Budgets data.
- **Keep the alerts topic for people.** The guardrail subscribes only the budget and the billing alarm to the alerts topic. Adding automation (Lambda, SSM) to `alerts.topic` yourself defeats the design, because a first-cent alert would then run it.
- **Actions run automatically.** The guardrail does not expose `approvalModel`, so the stop action runs with `AUTOMATIC` approval. To wait for an approval first, use `BudgetStopInstancesAction` directly with `approvalModel` set to `MANUAL`.
- **Actions notify e-mail subscribers.** Both actions notify the `emails` subscribers. They need between 1 and 11 subscribers, so `emails` must contain at least one address when `stopInstances` or `denyCompute` is given, otherwise construction fails with `subscribers must contain between 1 and 11 items, got 0`.
- **Deny needs a principal.** When `denyCompute` has no `roles`, `users` or `groups`, construction fails with `BudgetDenyAction needs at least one role, user or group`.
- **Only the listed instances stop.** `stopInstances.instanceIds` must contain between 1 and 100 items, otherwise construction fails with `instanceIds must contain between 1 and 100 items, got <n>`. Instances created later are not stopped until you add their IDs and deploy again.
- **Region of the stop action.** The guardrail does not expose the stop action's `region` prop. When the stack region is unresolved and `stopInstances` is set, construction fails with `region must be set when the stack region is unresolved`. Use a resolved stack region.
- **Billing alarm region.** `billingAlarmThresholdUsd` needs a stack in `us-east-1`. When the stack region is resolved to another region, construction fails with `BillingAlarm requires region us-east-1, got <region>`. When the stack region is unresolved, the construct adds the warning `cdk-constructless:unresolved-region` instead.
- **Budget limits.** `thresholds` must contain between 1 and 5 items, otherwise construction fails with `thresholds must contain between 1 and 5 items, got <n>`. `emails` must contain between 0 and 10 items, otherwise construction fails with `emails must contain between 0 and 10 items, got <n>`. Each `thresholds[<i>].percent` must be between 0.01 and 1000.
- **Free Plan availability is unconfirmed.** Check whether Budget Actions are available on the AWS Free Plan before you rely on `stopInstances` or `denyCompute` there.
- **Member accounts are not covered.** The guardrail does not expose `linkedAccountIds` or Cost Anomaly Detection. To budget one member account, use `CostBudget` directly.
- **Reverted actions are not re-run.** A reverted Budget Action is not evaluated again in the same period unless it is reset.
- **Construct ids.** The ids `Alerts`, `Budget`, `BillingAlarm`, `StopInstances`, `DenyCompute` and `ActionsRole` are part of the resource names. Changing one replaces the resources.
- **cdk-nag suppressions.** The guardrail adds no `suppressNag` entries of its own. The wrapped constructs acknowledge these findings:
  - `AwsSolutions-SNS2` on the alerts topic, always, because the guardrail passes no `masterKey`. Reason: "A KMS key costs 1 USD per month; this topic carries no sensitive data; pass masterKey to encrypt" (`AlertsTopic`).
  - For `stopInstances.target` `EC2`: `AwsSolutions-IAM5[Resource::*]`, `AwsSolutions-IAM5[Resource::arn:<AWS::Partition>:ssm:*:*:document/AWS-StopEC2Instance]`, `AwsSolutions-IAM5[Resource::arn:<AWS::Partition>:ssm:*:*:automation-execution/*]` and `AwsSolutions-IAM5[Resource::arn:<AWS::Partition>:ssm:*:*:automation-definition/AWS-StopEC2Instance:*]` on the execution role's default policy. Reason: "Budget Actions stop instances through SSM automation documents; AWS documents these wildcard resources" (`BudgetActionExecutionRole`). For `RDS`, the same four ids use `AWS-StopRdsInstance`.
  - `AwsSolutions-IAM5[Resource::*]` on the execution role's default policy when `denyCompute` is set. Reason: "IAM attach actions are scoped by iam:PolicyARN" (`BudgetActionExecutionRole`).

## Example

The stack is in `us-east-1` because the billing alarm metric exists only in that region. The example has a 5 USD monthly budget with three automatic steps: a billing alarm at 4 USD, a stop of one EC2 instance at 80 percent of the budget (4 USD), and a deny of compute for one role at 100 percent (5 USD). Every notification goes to `alerts@example.com`.

```typescript
import { App, Stack } from 'aws-cdk-lib';
import * as iam from 'aws-cdk-lib/aws-iam';
import { FinOpsGuardrail, StopInstancesTarget } from 'cdk-constructless';

const app = new App();
const stack = new Stack(app, 'Example', {
  env: { account: '123456789012', region: 'us-east-1' },
});

// The role that the deny policy attaches to. Use the role your lab workloads run as.
const labRole = new iam.Role(stack, 'LabRole', {
  assumedBy: new iam.AccountRootPrincipal(),
});

new FinOpsGuardrail(stack, 'LabGuardrail', {
  limitUsd: 5,
  emails: ['alerts@example.com'],
  billingAlarmThresholdUsd: 4,
  stopInstances: {
    target: StopInstancesTarget.EC2,
    instanceIds: ['i-0123456789abcdef0'],
    threshold: 80,
  },
  denyCompute: {
    roles: [labRole],
    threshold: 100,
  },
});
```
